## 独立虚拟测试

ROS_DOMAIN_ID=188、ROS_LOCALHOST_ONLY=1。本机 Nav2 MPPI 真实控制器，
静态 5 cm 栅格地图、虚拟 odom/TF；通过积分 /cmd_vel 更新虚拟机身位置。
不启动 Unitree 桥。走廊宽 0.80 m，起点 (1.2,2.0)，目标 (4.8,2.0)。
每步检查加余量的 0.96×0.60 m 矩形四角未超出直走廊边界。

| 配置 | 到达状态 | 轮廓越墙 | 耗时 |
|---|---|---|---|
| 修改前 | 成功 | 无 | 7.13 s |
| 修改后 | 成功 | 无 | 7.75 s |
| 修改后，启用障碍层，仅提供新鲜标记源，缺少背景清障源 | 成功 | 无 | 7.13 s |

前两例仅用静态层和膨胀层检查 MPPI 跟踪；第三例额外启用真实障碍层和两路来源，
证明 clearing-only 源暂缺不会把代价地图锁在过期状态。并未关闭标记源检查。
这些是单次运行，不能从耗时差声称变快或变慢。原配置也能通过，说明合成直通道
未复现用户现场故障。实验不含真实雷达误差、TF 延迟、底盘制动、打滑和转角。
采样得到的控制器瞬时指令可能略超配置上限；实机链路后续仍有平滑器和底盘限幅。

原始数据见 tracking_result.json 和 clearing_missing_result.json。
check.py、check_gate.py 保存独立测试代码；只应在独立 ROS 域执行。

是否仍有穿过通道的路径，才能区分几何不可行、定位/障碍误差和控制器偏好。
