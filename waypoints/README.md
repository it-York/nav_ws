`map_yaml` 相对 JSON 文件所在目录；坐标系为 `map`。每个点用唯一名称维护，
字段 `x`、`y`、`z` 单位为米，`yaw_deg` 为绕地图 Z 轴的朝向，单位为度。
0 度朝向地图 +X，90 度朝向 +Y。地图重建或坐标原点改变后需要重新采集。

## 记录点位

机器狗可以保持原地，不需要走到目标位置。以新增点位为例：

```bash
cd /home/koala2/nav_ws
./save_waypoint.sh "新点位名称"
```

等待提示出现后，在 RViz 使用 **2D Goal Pose**，点击并拖动设置朝向。
工具的 Topic 必须为 `/waypoint_pose`，Fixed Frame 必须为 `map`。
新导航启动时会从配置自动加载该工具。已经打开的 RViz 可在工具栏 **+** 中
添加 `rviz_default_plugins/SetGoal`（2D Goal Pose），然后在
**Panels → Tool Properties** 中把它的 Topic 改成 `/waypoint_pose`。

保存工具只订阅消息和写文件，不发送导航请求。原有 **Nav2 Goal** 仍然用于实际
导航，不能用于本工具记录；默认 `/goal_pose` 会触发导航，请先确认新工具的话题。
无需重启正在运行的导航。等待默认 120 秒，未收到点位则不会修改文件。

再次执行并使用不同名称即可保存多个点。更新同名点位：

```bash
./save_waypoint.sh "机房" --replace
```

也可直接编辑 JSON 中的点位名称、坐标和朝向；编辑文件不会自动发送导航目标。
原有 Nav2 Goal 通过 action 发送的历史目标无法由该订阅工具追溯，需重新选点。

## 不驱动机器狗的测试

### 只检查 JSON，不启动导航

此方式不需要机器狗开机，不连接 ROS，也不发送任何导航指令：

```bash
cd /home/koala2/nav_ws

# 列出全部点位，并检查点位文件和地图文件路径
python3 scripts/goto_waypoint.py --list

# 检查指定点位并显示其坐标、朝向和关联地图
python3 scripts/goto_waypoint.py "机房" --dry-run
```

可以将“机房”替换为上表中的任意名称。检查全部点位可执行：

```bash
for name in "老板办公室" "公司前台" "公司展厅" "坐标原点" "办公室5" "办公区1" "机房"; do
  python3 scripts/goto_waypoint.py "$name" --dry-run || break
done
```

`--dry-run` 只检查文件格式、地图文件是否存在以及坐标和朝向是否为有效数值，
不会检查目标是否位于障碍物内，也不能证明目标可达。

### 在 RViz 查看规划路线，机器狗保持不动

此方式仍需雷达、定位和导航正常运行。先在原导航终端按 `Ctrl+C` 退出旧导航，
确认之前带 `--motion` 启动的运动节点已经退出，也没有其他运动控制程序仍在运行。
不能通过再启动一套无运动导航来禁用旧的运动节点。

终端一启动默认无运动模式，**不要加 `--motion`**：

```bash
cd /home/koala2/nav_ws
./start_nav.sh
```

该脚本默认传入 `enable_motion:=false`，不启动运动模式管理器和运动控制桥接节点。
等待 RViz 中地图、定位正常并对齐后，在终端二发送一个测试目标：

```bash
cd /home/koala2/nav_ws
./goto_waypoint.sh "机房"
```

这条命令会向 Nav2 发送目标，Nav2 会进行规划和控制计算；在上述无运动配置下，
本工作空间不会把导航速度转换为机器狗执行指令。观察 RViz 中的全局路径，
检查目标位置是否正确、路线是否经过预期通道。

观察完成后，在发送目标的终端按 `Ctrl+C`，等待取消确认，再测试下一个点位。
由于机器狗没有实际移动，Nav2 可能报“无进展”或导航失败，这是此测试方式的预期限制。
它不能验证实际到达精度、转弯效果、动态避障或制动距离，也不是运动仿真。

## 按名称导航

以下步骤用于真实运动。结束无运动测试并退出原导航后，终端一启动导航
（已有导航运行时不要重复启动）：

```bash
cd /home/koala2/nav_ws
./start_nav.sh --motion
```

在 RViz 确认定位与地图对齐后，终端二选择已保存的点位：

```bash
cd /home/koala2/nav_ws
./goto_waypoint.sh --list
./goto_waypoint.sh "老板办公室" --dry-run
./goto_waypoint.sh "老板办公室"
```

最后一条命令会发送真实的 Nav2 导航目标；新目标可能替换正在执行的目标。
程序先比对 `/map_server` 的地图文件路径，再将 `yaw_deg` 转换为四元数，
通过 `/navigate_to_pose` 发送带当前时间戳的目标，并输出接收状态、剩余距离和结果。
Ctrl+C 会请求取消本程序发出的目标，并等待确认；若通信失败则按终端提示在 RViz 检查。
只有无运动模式运行、且没有遗留运动桥接或其他运动控制程序时，
底盘不会因本工作空间的导航指令运动。

`--file /绝对路径/其他点位.json` 可选择其他文件。路径检查不能检测同名地图重建，
重建后仍需重新采集点位。编辑 JSON 本身不会移动机器狗，执行导航命令才会发送目标。
